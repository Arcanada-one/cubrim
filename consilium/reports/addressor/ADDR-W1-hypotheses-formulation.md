## Канонический контракт честности (применяется к каждой гипотезе)

Из статей проекта (source-of-truth) и гочей Cubrim-1:

1. **Pigeonhole-предел.** Фиксированный короткий код различает лишь конечное число состояний; один короткий адрес не может однозначно обозначать каждую длинную последовательность без дополнительной информации. Адрес имеет смысл только вместе с каталогом, где объект уже находится.
2. **Полная стоимость.** Для каждой гипотезы: `total_cost = address + metadata + residual + amortized(matrix + catalog + distribution + sync + integrity)`. Выигрыш существует только если total_cost < локальное сжатие того же входа.
3. **Information conservation (Gotcha #7/#8 Cubrim-1).** Любая карта/перестановка/индекс, которую декодер должен получить, — это ветка декодера и статья расхода. Модель с числом cost-термов меньше числа веток декодера (Gotcha #6) — несостоятельна.
4. **Первая передача не бесплатна.** Каждый блок матрицы кем-то когда-то передан впервые; «у получателя уже есть» — это амортизация, а не магия.

> **OPERATOR CLARIFICATION 2026-07-14:** «16–64 байта» в этом документе — НЕ жёсткое требование, а стремление сократить ссылку до разумного минимума (порядка десятков–сотен байт). Критерий выигрыша Адресатора: net-байты (address + metadata + residual + amortized matrix) < локальное сжатие при ссылке ≪ payload. Размер ссылки — метрика для минимизации, не гейт; формулировки ниже, где 16–64 Б читается как порог (особенно AH-05 «единственный честный 16–64 Б»), считать переформулированными в этом смысле. БД-карточка AH-05 и сайт обновлены; pigeonhole-предел и total_cost-контракт остаются в силе без изменений.

**Формат гипотезы (канон research-loop):** «если применить X, то метрика Y изменится на классе данных Z, потому что механизм M» + физическая модель/каталог, address target (16–64 B, где применимо), predicted lever, falsification test, честный потолок, total_cost-разбор.

**Ceiling-категории** (используются в карточках):
- `identity-dedup` — честные 16–64 B на файл/чанк возможны ТОЛЬКО здесь (объект уже в каталоге, exact match);
- `shared-context` — общая матрица улучшает энтропийное кодирование (словарь/фрагменты), но residual остаётся потоком, а не ссылкой;
- `near-match-delta` — адрес ближайшего + дельта;
- `structural-no-win` — класс/механизм, где адресатор не может выиграть у локального сжатия (анти-гипотеза, фиксируем границу);
- `infra-cost` — гипотеза о стоимости инфраструктуры (каталог/синхронизация/доверие/приватность/экономика), входящей в total_cost всех остальных.

## Ось A — физическая природа Универсальной Матрицы Данных Валентовых

### AH-01 · Матрица-как-словарь (shared dictionary) — `shared-context`
**Если** зафиксировать versioned-immutable глобальный словарь (обученный zstd `--train`-методом на репрезентативном мультидоменном корпусе; секция матрицы «общая статистика мира») и передавать `dict_id (8 B) + поток, сжатый со словарём`, **то** передаваемые байты на классе **мелких структурированных файлов (<128 KiB: JSON/HTML/логи/конфиги)** снизятся относительно локального zstd без словаря, **потому что** малый файл не успевает выучить собственную статистику, а словарь даёт контекст с первого байта.
- Физическая модель: неизменяемый блоб словаря (МиБ—ГиБ), доставлен заранее, амортизирован по всем файлам устройства.
- Address target: неприменим (это не ссылочная схема; residual = весь сжатый поток).
- Predicted lever: заметный на smalls; **предсказание** ≥25% на классе Z, →0 на файлах ≥4 MiB (внутренняя статистика доминирует).
- Falsification: корпус реальных мелких файлов; если выигрыш <25% на smalls ИЛИ амортизация словаря не окупается при реалистичном числе файлов на устройстве — NO-GO.
- Честный потолок: словарь покрывает «головы» распределения; НЕ даёт 16–64 B ссылок; это baseline, который любые фрагментные схемы (AH-07) обязаны бить.
- total_cost: address 8 B + metadata (frame) + residual (весь поток) + amortized(dict_size/N_files_на_устройстве; distribution — однократная доставка словаря).

### AH-02 · Матрица-как-CAS чанков (content-addressable store) — `identity-dedup`
**Если** представить матрицу как глобальный CAS неизменяемых CDC-чанков (Rabin content-defined chunking, средний чанк ~8 KiB), накопленных с ранее виденных данных на многих устройствах, **то** метрика net-передаваемых байт на классе **повторно встречающегося контента (OS-образы, пакеты/библиотеки, пересылаемые файлы, бэкапы)** упадёт до последовательности хэш-ссылок (~32 B / 8 KiB ≈ 0.4% на чанк при hit), **потому что** получатель уже физически хранит чанки, а CDC устойчив к вставкам/сдвигам.
- Физическая модель: облачный/распределённый чанк-стор + локальный кэш; каталог = хэш-индекс чанков.
- Address target: 32 B SHA-256 на чанк + манифест файла (соответствует операторским 16–64 B на ссылку).
- Predicted lever: выигрыш = hit_rate × (1 − 0.4%) по массе; литература по enterprise-backup dedup даёт 10–30× (внешняя ссылка, НЕ наше измерение).
- Falsification: измерить chunk-hit-rate по массе на реалистичной кросс-девайсной смеси; если <30% массы — класс узок, GO только как режим в router (AH-18).
- Честный потолок: на уникальных данных hit→0 и схема ПРОИГРЫВАЕТ локальному сжатию (хэши несжимаемы; манифест — чистый оверхед). Первое появление чанка платит полную цену + upload (AH-19).
- total_cost: addresses + манифест + residual (новые чанки целиком) + amortized(хранение всего CAS × время + каталог AH-09/10 + доверие AH-21).

### AH-03 · Генерируемая матрица (PRNG/π/де Брёйн) — `structural-no-win` (анти-гипотеза)
**Если** сделать матрицу детерминированно ГЕНЕРИРУЕМОЙ (PRNG-развёртка, цифры π, де Брёйновская последовательность порядка k), чтобы стоимость её дистрибуции была ~0, **то** метрика total_cost на ЛЮБОМ классе реальных данных не улучшится, **потому что** (а) случайно сгенерированный пул размера M содержит конкретную 64-байтовую последовательность с вероятностью ~M/2^512 — ноль для любого физического M; (б) де Брёйн содержит ВСЕ k-граммы, но адрес k-грамма в нём занимает ровно столько же бит, сколько сам k-грамм: адрес в исчерпывающем каталоге ≥ содержимого (information conservation, родня Gotcha #7).
- Predicted: NO-GO строгий; формулируем, чтобы канонически закрыть «магический» вариант и получить теорему-потолок в явном виде.
- Falsification (симметричная): продемонстрировать хоть один реальный класс, где адресация в генерируемый пул даёт total_cost меньше энтропийной стоимости — тогда я неправ (не ожидаю).

### AH-04 · Occupancy-bitmap N-куба как секция матрицы — `shared-context`, риск `structural-no-win`
**Если** операторскую формулу «биты указывают, какие байты N-мерного куба существуют» реализовать как succinct rank/select bitmap (RRR) над φ-геометрией куба Cubrim-1, **то** метрика стоимости передачи МНОЖЕСТВА занятых координат на классе **разрежённых входов (ρ<0.3)** приблизится к информационному минимуму log2 C(L,k), **потому что** RRR кодирует множества почти оптимально.
- Честный потолок (главное): occupancy-set — это «какие», но не «в каком порядке» и не «какие значения»; восстановление файла требует ещё перестановку + значения, а value stream в Cubrim-1 — 99%+ выхода (Gotcha #2), и переданная перестановка платится полностью (Gotcha #7).
- Predicted: как САМОСТОЯТЕЛЬНЫЙ носитель — NO-GO; как поисковый ключ каталога — см. AH-14.
- Falsification: измерить долю информации файла в occupancy-set относительно полной; если <5% на реальных классах — рычаг мёртв как носитель, гипотеза переквалифицируется в ключевую роль (AH-14).

## Ось B — механика 16–64-байтового адреса

### AH-05 · Identity-dedup целого файла: единственный честный 16–64 B — `identity-dedup`
**Если** адрес = криптохэш целого файла (32 B) + метаданные (до 64 B суммарно) при условии, что файл уже есть в каталоге, **то** метрика передаваемых байт на классе **точных повторов (инсталляторы, популярные медиа-решеры, пакеты)** падает до 32–64 B на файл ЛЮБОГО размера, **потому что** это ровно случай «объект уже находится в каталоге» из канона — pigeonhole не нарушен: различаем только то, что уже сохранено.
- Predicted lever: крупнейший честный рычаг трека; масса whole-file-дубликатов в реальных коллекциях — 20–50% по литературе enterprise (внешняя ссылка, не измерение).
- Falsification: собрать file-level dup-mass статистику на реальной кросс-девайсной смеси; <10% массы → рычаг узок, приоритет оси падает.
- Честный потолок: работает ТОЛЬКО на exact match; один бит различия — и это уже AH-15. total_cost: 32–64 B + amortized(каталог + хранение копии в матрице + первая передача AH-19).

### AH-06 · Байтовая гистограмма+хэш как носитель данных — `structural-no-win` (анти-гипотеза)
**Если** использовать операторскую «характеристику: каких байтов сколько раз повторилось» (byte-histogram) + хэш как АДРЕС для восстановления, **то** реконструкция на любом нетривиальном классе невозможна за вычислимое время, **потому что** гистограмма уничтожает порядок: число перестановок мультимножества L!/∏cᵢ! (для 1 KiB текста ~10^2500); хэш сужает до одного кандидата, но поиск канонического представителя по хэшу — невычислимый перебор, а явное указание перестановки стоит log2(L!/∏cᵢ!) бит ≈ энтропия самого файла.
- Predicted: NO-GO как носитель. Честная роль пары (histogram, hash) — интегрити/фингерпринт/поисковый ключ (AH-14), это фиксируем в канон, чтобы видение оператора получило корректную инженерную форму.
- Falsification (симметричная): предъявить класс, где мультимножество почти определяет порядок (например, отсортированные данные) — там носитель работает; ожидаю нишу ≪1% реальных данных.

### AH-07 · Двухуровневый адрес фрагмента (matrix_version + section + offset + len) — `shared-context`
**Если** адрес фрагмента = (matrix_version 4 B, section 4 B, offset 6 B, len 2 B, флаги/transform 2–8 B) ≈ 16–24 B на фрагмент, уже лежащий в матрице, **то** метрика net-байт на классе **структурированных повторов (boilerplate-хедеры, лицензии, шаблоны документов, обёртки форматов, копипаст-код)** снизится пропорционально covered_fraction × (1 − address_cost/fragment_len), **потому что** типовые фрагменты частотны и длинны (сотни байт — КиБ), а ссылка дешевле фрагмента.
- Predicted lever: покрытие фрагментами ≥256 B на office/code/web классах 20–60% (предсказание).
- Falsification: скан корпуса против собранной секции матрицы; покрытие <15% ИЛИ экономия ≤ эквивалента zstd-со-словарём (AH-01) при равной амортизации — NO-GO (словарь subsumes, Gotcha #11-паттерн: сравнивать сквозь настоящий бэкенд).
- total_cost: address×кол-во + разметка границ (metadata!) + residual + amortized(секция матрицы). Разметка «где вставить фрагмент» — ветка декодера, платится.

### AH-08 · Энтропийное кодирование потока адресов — `shared-context`
**Если** поток ссылок в матрицу кодировать rANS-бэкендом (частые фрагменты — короткие коды), **то** средняя стоимость ссылки на классе **любых данных с Zipf-распределением обращений** упадёт с номинальных 16–32 B до эффективных единиц байт, **потому что** распределение обращений к общей матрице сильно скошено — топ-фрагменты покрывают большинство обращений.
- Predicted: топ-1% фрагментов ≥50% обращений (предсказание по Zipf-аналогии).
- Falsification: смоделировать распределение обращений на web/code корпусе; если оно близко к равномерному — рычага нет.
- Честный потолок: это оптимизация ПОВЕРХ AH-02/07; сама по себе выигрыша не создаёт, и она уже «почти есть» в rANS-бэкенде Cubrim-1 — заряжать сквозь настоящий кодек (Gotcha #11), иначе поймаем subsumption-мираж.

## Ось C — каталог / индекс

### AH-09 · MPH-каталог (minimal perfect hashing) — `infra-cost`
**Если** индекс «какие последовательности есть в матрице» строить на MPH (~2–3 бита/ключ) + короткий отпечаток (8–16 бит), с криптоподтверждением полным хэшем при hit, **то** метрика catalog_bytes/chunk станет достаточно малой, чтобы каталог миллиардного стора помещался в единицы ГиБ, **потому что** MPH почти оптимален по памяти, а дешёвый отпечаток отсекает почти все ложные срабатывания до сетевого запроса.
- Falsification: если требуемый для безопасного UX fp-rate не достигается 16-бит отпечатком и каталог раздувается настолько, что съедает амортизацию у устройств с малым N файлов — NO-GO конфигурации; замер кривой fp/bytes.
- Роль: статья `amortized catalog` в total_cost всех identity/near-match гипотез.

### AH-10 · Bloom-предфильтр отправителя — `infra-cost`
**Если** отправитель держит локальный Bloom-фильтр каталога (fp ~1%), **то** число сетевых lookup'ов на классе **типичного user-микса** упадёт до ~hit_rate × (1+fp) доли чанков, **потому что** фильтр отсекает заведомо-новые чанки локально, без RTT.
- Честный потолок/скрытая статья: фильтр надо СИНХРОНИЗИРОВАТЬ с растущей матрицей; если трафик обновлений фильтра превышает сэкономленные lookup'ы (высокий churn) — NO-GO; синхронизация каталога — обязательная статья total_cost, не нулевая.
- Falsification: модель churn-rate матрицы vs трафик обновлений на реалистичном профиле добавлений.

## Ось D — экономика амортизации

### AH-11 · Порог окупаемости N* (break-even) — `infra-cost`
**Если** формализовать B(N) = Σsavings(N) − M_size − C_catalog_sync(N) − C_residual_overhead(N) по N файлов/устройств, **то** для фиксированной матрицы существует измеримый порог N*, причём на классе **enterprise-backup/однородных флотов** N* достигается при реалистичных размерах флота, а на классе **уникального персонального контента (свои фото/видео)** N*→∞, **потому что** savings пропорциональны кросс-девайсной повторности, которая у уникального контента ~0.
- Falsification: посчитать N* на 2–3 реальных смесях; классы с N* больше реалистичного флота — канонизировать как «вне рынка адресатора».
- Продукт гипотезы: формула и таблица N* по классам — измеритель честности всего трека.

### AH-12 · Деградация замороженной матрицы (drift) — `infra-cost`
**Если** матрицу заморозить (immutable v1 — как требует канон «набор неизменяемых блоков»), **то** метрика hit-rate на классе **свежего контента (новости, обновляемый софт, новые форматы)** будет монотонно деградировать со временем с измеримой скоростью d(hit)/dt, **потому что** распределение реальных данных нестационарно, а замороженная матрица — снимок прошлого.
- Predicted: полураспад полезности словарных секций — быстрее, чанковых — медленнее (предсказание, без чисел).
- Falsification: hit-rate(t) на датированных снапшотах корпуса; результат определяет политику версий, а КАЖДАЯ новая версия матрицы — снова distribution-cost в total_cost.

## Ось E — надстройка над геометрией куба Cubrim-1

### AH-13 · φ-нормализованные ключи фрагментов (кросс-контейнерный dedup) — `near-match-delta`, риск `structural-no-win`
**Если** ключи фрагментов матрицы строить по нормал-форме куба Cubrim-1 (мультимножество значений секции + локальная карта), а не по сырым байтам, **то** hit-rate кросс-файлового dedup на классе **«тот же payload в разных обёртках» (tar vs zip-stored vs сдвиг заголовка)** вырастет относительно сырого CDC, **потому что** φ-нормализация абстрагирует позиционный сдвиг внутри секции.
- Честный потолок: восстановление платит за перестановку (Gotcha #7); выигрыш существует только там, где плата за пер-фрагментную перестановку < ценность раскрытого совпадения. CUBR-0032 закрыл это ВНУТРИ файла; здесь — НАДфайловый случай, который тот замер не покрывал, поэтому гипотеза законна, но презумпция — против неё.
- Falsification: charged end-to-end на паре «same payload, shifted container»; (совпадение − перестановочная плата) ≤ CDC-baseline → NO-GO.

### AH-14 · (occupancy-hash, histogram-hash) как СОСТАВНОЙ ПОИСКОВЫЙ КЛЮЧ — `near-match-delta`
**Если** пару сигнатур секции куба (хэш occupancy-bitmap, хэш байт-гистограммы) использовать как LSH-подобный ключ каталога для поиска ПОХОЖИХ секций (не как носитель данных!), **то** recall поиска near-duplicate на классе **версионированных/слабо изменённых данных** вырастет при фиксированной precision относительно чистого криптохэш-чанкинга, **потому что** эти сигнатуры устойчивы к малым локальным правкам, тогда как криптохэш ломается от одного бита.
- Это честная инженерная форма операторской идеи «хэш того, сколько каких байтов повторилось».
- Falsification: замер recall/precision на multiversion-корпусе (уже есть в бенче Cubrim-1) против simhash/CDC-baseline; прирост recall <10 п.п. — сложность не окупается, NO-GO.

### AH-15 · Near-match адрес + дельта (rsync-родня) — `near-match-delta`
**Если** адрес указывает ближайший фрагмент матрицы, а передаётся только дельта (rolling-hash/bsdiff-механика), **то** метрика net-байт на классе **версионированных данных (код, документы, бэкап-цепочки)** упадёт до address + delta ≪ full, **потому что** соседние версии близки по содержимому и дельта мала.
- Predicted lever: крупный (rsync-практика — внешняя ссылка, не измерение).
- Falsification: charged-замер на multiversion: address + delta + доля каталога против ЛОКАЛЬНОГО zstd -19 со словарём; не бьёт — NO-GO. Отдельно: rolling-hash-индекс по ВСЕЙ матрице — тяжёлая статья каталога (в total_cost).
- Честный потолок: умирает на пережатых/перешифрованных версиях (дельта = весь файл, класс уходит в AH-16).

## Ось F — граница применимости против локального сжатия

### AH-16 · Класс невозможности: уже-сжатое/шифрованное уникальное — `structural-no-win` (анти-гипотеза)
**Если** применить ЛЮБУЮ адресацию к классу **уникальных уже-сжатых/зашифрованных потоков (личные .jpg/.mp4/.zst, TLS-дампы)**, **то** total_cost будет строго ≥ исходника (адреса+манифест — чистый оверхед), **потому что** такие потоки статистически неотличимы от случайных, в глобальном пуле повторно не встречаются (hit-rate ~0), а локальному сжатию там тоже нечего брать — но оно хотя бы не добавляет оверхед.
- Predicted: подтверждение = 0 whole-chunk hits на корпусе уникальных медиа.
- Роль: канонизировать ГРАНИЦУ — исключение составляют только точные ре-шеры (это AH-05, другой класс).
- Falsification (симметричная): ненулевой систематический hit на уникальном медиа означал бы скрытую структурную повторность — интересно, но не ожидается.

### AH-17 · Инверсия на мелких уникальных файлах — `structural-no-win` (граница)
**Если** применить чанк-адресацию к классу **мелких уникальных файлов (<4 KiB)**, **то** total_cost станет ХУЖЕ локального сжатия, **потому что** фиксированные издержки (манифест, минимум один 32 B адрес, запись в каталог, синхронизация) превышают возможную экономию, а мелочь и локально жмётся дёшево.
- Продукт: измеренная точка инверсии X (байт), ниже которой Адресатор обязан маршрутизировать вход в локальный кодек (правило для AH-18).
- Falsification: если инверсии нет (адресация выигрывает даже на 1 KiB uniques) — я неправ; ожидаю обратное.

### AH-18 · Router: адресатор ⊕ Cubrim-1 (competitive selection) — `identity-dedup`+`shared-context`
**Если** построить двухфазный кодек — фаза 1: exact-dedup по матрице (whole-file AH-05, затем CDC AH-02), фаза 2: residual → локальный кодек Cubrim-1, — **то** total_cost на классе **реальных смешанных user-миксов** будет ≤ min(каждый метод поодиночке) + ε и строго лучше обоих на смесях с ненулевой dup-массой, **потому что** рычаги ортогональны: глобальная повторность и локальная статистика не конкурируют за одни байты.
- Архитектурный паттерн — регрессия-стойкий competitive selection (Gotcha #4: encoder пишет min(new, baseline) + scheme-байт).
- Falsification: если интеграционный оверхед (манифест, границы фаз) съедает выигрыш при низкой dup-массе — измерить порог dup-массы, ниже которого фаза 1 выключается.

## Ось G — системная честность (распределение, доверие, приватность)

### AH-19 · Первая передача и коэффициент повторного обращения r — `infra-cost`
**Если** учесть, что каждый блок матрицы был кем-то передан впервые, **то** глобальный net-выигрыш системы на классе контента с коэффициентом повторного обращения r (среднее число получателей блока) положителен только при r > r* ≈ 1 + overhead_share, **потому что** первая доставка платит полную цену, и её окупают только повторные обращения.
- Predicted: у популярного контента r ≫ 1 (CDN-экономика), у long-tail r ≈ 1 → матрицу нужно КУРИРОВАТЬ по популярности, а не копить всё подряд.
- Falsification: r-распределение по классам на реальном трафик-профиле; если медиана r по байтам ~1 и хвост доминирует массу — некурируемая матрица глобально убыточна.

### AH-20 · Секционная (частичная) доставка матрицы — `infra-cost`
**Если** разбить матрицу на тематические секции (код / документы / web / медиа-контейнеры) и устройство держит только релевантные («пользователь загружает только нужные разделы» — прямой канон статьи), **то** amortized matrix cost на устройство упадёт ~пропорционально доле секций при потере hit-rate МЕНЬШЕЙ, чем эта доля, на классе **тематически сконцентрированных устройств**, **потому что** данные одного устройства тематически локальны.
- Falsification: кривая hit-rate(доля секций); если для 80% hit нужно >50% секций — тематическая локальность слаба, секционирование амортизацию не спасает.

### AH-21 · Стоимость доверия (Merkle/verification) — `infra-cost`
**Если** матрица распределённая (IPFS-подобная), **то** каждый hit несёт криптоверификацию: полный хэш блока + Merkle-путь до доверенного корня в манифесте, что добавляет измеримую надбавку к address_cost, **потому что** доверие в открытой сети не бесплатно, а отравленная матрица = порча данных на тысячах устройств (Non-Harm: интегрити обязательна, не опциональна).
- Predicted: на высокоповторных классах надбавка <5% выигрыша; на низкоповторных — усугубляет проигрыш.
- Falsification: замер Merkle-оверхеда на реальном манифесте типового файла.

## Ось H — метод (process-гипотезы волны)

### AH-22 · Charged-стенд ПЕРЕД экспериментами — `infra-cost` (process)
**Если** до любых измерений построить honest-accounting стенд, который для КАЖДОЙ ветки декодера-восстановителя считает отдельный cost-терм (address, metadata, residual, amortized matrix/catalog/sync/integrity — прямое обобщение Gotcha #6/#8), **то** kill-rate гипотез на модельной стадии вырастет, а доля falsely-optimistic GO упадёт, **потому что** Cubrim-1 уже дважды ловил фальшивый GO на незаряженных моделях (CUBR-0026: непосчитанные fallback-таблицы; CUBR-0032: непосчитанная φ-карта).
- Falsification: если первая же реализация вскроет GO, пропущенный заряженной моделью, — стенд неполон, чинить немедленно.

### AH-23 · Реализм корпуса (кросс-девайсные смеси, не синтетика) — `infra-cost` (process)
**Если** корпус адресатора собрать из реальных кросс-девайсных смесей с временными снапшотами (несколько машин: код+доки+медиа+бэкапы), **то** оценки dup-mass/hit-rate окажутся НИЖЕ синтетических на измеримую величину, **потому что** синтетика наследует статистику собственного генератора — это ρ=1-ловушка Cubrim-1 (Gotcha #1) в новом обличье: корпус, который «сам себя повторяет», тестирует скаффолдинг, а не принцип.
- Falsification: параллельная оценка на синтетическом и реальном корпусах; расхождение <10% — синтетика допустима, я неправ.

### AH-24 · Приватность как жёсткое ограничение dedup — `infra-cost`
**Если** dedup кросс-пользовательский, **то** сам факт hit/miss утекает информацию («этот файл у кого-то уже есть» — известный класс атак на облачную дедупликацию), поэтому на классе **приватных данных** допустима только convergent encryption с per-user/domain солью, которая УБИВАЕТ кросс-пользовательский dedup, **потому что** одинаковые открытые тексты перестают давать одинаковые шифротексты между доменами.
- Predicted: privacy-safe адресатор ограничен публичным/общим контентом + dedup внутри доверенного домена; глобальный hit-rate под privacy-режимом заметно ниже наивного.
- Falsification: модель режимов (публичные блобы конвергентно + приватные локально); если существует режим с ≥80% исходного hit-rate — ограничение мягче предсказанного.

## Сводка: где адресатор НЕ может выиграть у локального сжатия (фиксация границы)

1. **Уникальные высокоэнтропийные данные** (личные медиа, шифртексты) — hit-rate ~0, адреса/манифест — чистый оверхед (AH-16).
2. **Мелкие уникальные файлы** ниже точки инверсии X — фиксированные издержки каталога больше экономии (AH-17).
3. **Генерируемые/исчерпывающие матрицы** — адрес ≥ содержимого, information conservation (AH-03).
4. **Гистограмма/хэш как носитель** — порядок не восстановим за вычислимое время, а его явная передача стоит энтропию файла (AH-06).
5. **Long-tail контент с r≈1** — первая передача не окупается повторными обращениями (AH-19).
6. **Классы, где выигрыш ≤ zstd-со-словарём** при равной амортизации — фрагментная адресация вырождается в словарь (AH-07 falsification-ветка).

Единственный класс, где 16–64 B на объект ЧЕСТНО достижимы, — exact-match по каталогу (AH-05/AH-02): «адрес имеет смысл только вместе с каталогом, где объект уже находится» — прямой канон.
