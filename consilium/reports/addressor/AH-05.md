## Каноническая формулировка (если X → Y на Z, потому что M)

Если адрес = криптохэш целого файла (32-64B с метаданными) при объекте, уже лежащем в каталоге, то передача на классе точных повторов падает до 32-64B на файл любого размера, потому что различаем только уже сохранённое (pigeonhole не нарушен).

## total_cost = address + metadata + residual + amortized(matrix/catalog/distribution/sync/integrity)

address: 32 B криптохэш + ≤32 B метаданных (суммарно ≤64 B) · metadata: запись каталога · residual: 0 при exact-hit, ВЕСЬ файл при miss · amortized: хранение копии в матрице + каталог + первая передача файла (AH-19).

## Честный потолок / граница no-win

Не выигрывает: любой не-exact-match (один изменённый бит → это уже AH-15); уникальные файлы.

## Авторский разбор (из синтез-отчёта волны 1)

### AH-05 · Identity-dedup целого файла: единственный честный 16–64 B — `identity-dedup`
**Если** адрес = криптохэш целого файла (32 B) + метаданные (до 64 B суммарно) при условии, что файл уже есть в каталоге, **то** метрика передаваемых байт на классе **точных повторов (инсталляторы, популярные медиа-решеры, пакеты)** падает до 32–64 B на файл ЛЮБОГО размера, **потому что** это ровно случай «объект уже находится в каталоге» из канона — pigeonhole не нарушен: различаем только то, что уже сохранено.
- Predicted lever: крупнейший честный рычаг трека; масса whole-file-дубликатов в реальных коллекциях — 20–50% по литературе enterprise (внешняя ссылка, не измерение).
- Falsification: собрать file-level dup-mass статистику на реальной кросс-девайсной смеси; <10% массы → рычаг узок, приоритет оси падает.
- Честный потолок: работает ТОЛЬКО на exact match; один бит различия — и это уже AH-15. total_cost: 32–64 B + amortized(каталог + хранение копии в матрице + первая передача AH-19).
