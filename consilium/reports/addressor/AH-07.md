## Каноническая формулировка (если X → Y на Z, потому что M)

Если адрес фрагмента = (version,section,offset,len,flags) ~16-24B на фрагмент в матрице, то net-байты на структурированных повторах снизятся на covered_fraction*(1-address/fragment_len), потому что типовые фрагменты длинны и частотны.

## Поля карточки

- **Физическая модель / каталог:** ссылка дешевле длинного частотного фрагмента
- **Класс данных (Z):** boilerplate, лицензии, шаблоны, обёртки форматов, копипаст-код
- **Address target:** 24 B
- **Predicted lever (предсказание, НЕ измерение):** покрытие фрагментами >=256B на office/code/web 20-60% (предсказание)
- **Ceiling-категория:** `shared-context`
- **Falsification test:** скан корпуса: покрытие <15% ИЛИ экономия <= zstd-со-словарём -> NO-GO (AH-01 subsumes)
- **measured_result:** null — измерений не было, статус OPEN честен
- **code_ref:** null — кода ещё нет
- **Source:** operator vision + brotli static dict analogue

## total_cost = address + metadata + residual + amortized(matrix/catalog/distribution/sync/integrity)

address: 16–24 B × число фрагментов · metadata: разметка границ/точек вставки (отдельная ветка декодера — платится по Gotcha #6) · residual: непокрытые байты через локальный кодек · amortized: секции матрицы с фрагментным пулом.

## Честный потолок / граница no-win

Не выигрывает: покрытие фрагментами <15%; и всегда, когда zstd-со-словарём (AH-01) даёт ту же экономию дешевле — тогда схема вырождается в словарь.

## Авторский разбор (из синтез-отчёта волны 1)

### AH-07 · Двухуровневый адрес фрагмента (matrix_version + section + offset + len) — `shared-context`
**Если** адрес фрагмента = (matrix_version 4 B, section 4 B, offset 6 B, len 2 B, флаги/transform 2–8 B) ≈ 16–24 B на фрагмент, уже лежащий в матрице, **то** метрика net-байт на классе **структурированных повторов (boilerplate-хедеры, лицензии, шаблоны документов, обёртки форматов, копипаст-код)** снизится пропорционально covered_fraction × (1 − address_cost/fragment_len), **потому что** типовые фрагменты частотны и длинны (сотни байт — КиБ), а ссылка дешевле фрагмента.
- Predicted lever: покрытие фрагментами ≥256 B на office/code/web классах 20–60% (предсказание).
- Falsification: скан корпуса против собранной секции матрицы; покрытие <15% ИЛИ экономия ≤ эквивалента zstd-со-словарём (AH-01) при равной амортизации — NO-GO (словарь subsumes, Gotcha #11-паттерн: сравнивать сквозь настоящий бэкенд).
- total_cost: address×кол-во + разметка границ (metadata!) + residual + amortized(секция матрицы). Разметка «где вставить фрагмент» — ветка декодера, платится.

## Verdict — NO-GO (2026-07-14, W1-fragments-v1 → v1b-fair, MEASURED)

Оба пре-регистрированных условия сработали: покрытие фрагментами ≥256 Б = **10.69%** (<15%) И экономия ≤ zstd-словаря (per-file: 0.2781 без каталога / 0.3017 с каталогом против словаря 0.2664). Первая версия пробы показала мнимый выигрыш — стенд AH-22 поймал конфаунд (солидный residual против пофайловых базлайнов); после выравнивания плеч выигрыш исчез (solid: 0.228 с каталогом против 0.2153 локального солидного). **NO-GO** — фрагментная адресация на этом классе вырождается в словарь, который дешевле.
