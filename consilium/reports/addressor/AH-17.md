## Каноническая формулировка (если X → Y на Z, потому что M)

Если применить чанк-адресацию к мелким уникальным файлам (<4 KiB), то total_cost станет хуже локального сжатия, потому что фиксированные издержки (манифест, адрес, каталог, sync) превышают экономию.

## Поля карточки

- **Физическая модель / каталог:** константные издержки не амортизируются малым размером
- **Класс данных (Z):** small unique files (<4 KiB)
- **Address target:** не применим (схема не ссылочная / инфра-статья)
- **Predicted lever (предсказание, НЕ измерение):** измеренная точка инверсии X — правило маршрутизации для AH-18
- **Ceiling-категория:** `structural-no-win`
- **Falsification test:** net bytes vs zstd по бинам размера; отсутствие инверсии опровергло бы (не ожидается)
- **measured_result:** null — измерений не было, статус OPEN честен
- **code_ref:** null — кода ещё нет
- **Source:** фиксация границы vs локальное сжатие

## total_cost = address + metadata + residual + amortized(matrix/catalog/distribution/sync/integrity)

константные статьи (манифест + ≥1 адрес + запись каталога + sync) при size→0 дают cost/size→∞; экономия ограничена размером файла.

## Честный потолок / граница no-win

Не выигрывает: все файлы ниже точки инверсии X — измеренный X становится правилом маршрутизации router'а (AH-18) в локальный кодек.

## Авторский разбор (из синтез-отчёта волны 1)

### AH-17 · Инверсия на мелких уникальных файлах — `structural-no-win` (граница)
**Если** применить чанк-адресацию к классу **мелких уникальных файлов (<4 KiB)**, **то** total_cost станет ХУЖЕ локального сжатия, **потому что** фиксированные издержки (манифест, минимум один 32 B адрес, запись в каталог, синхронизация) превышают возможную экономию, а мелочь и локально жмётся дёшево.
- Продукт: измеренная точка инверсии X (байт), ниже которой Адресатор обязан маршрутизировать вход в локальный кодек (правило для AH-18).
- Falsification: если инверсии нет (адресация выигрывает даже на 1 KiB uniques) — я неправ; ожидаю обратное.

## Verdict — NO-GO (2026-07-14, W1-inversion-v1, MEASURED)

Точка инверсии X по размеру ОТСУТСТВУЕТ на реальном миксе (8.5 ГиБ, per-file transmission, charged): адресатор выигрывает во всех 8 бинах, включая ≤1 КиБ (0.5225 vs 0.5937 local; 76 360 файлов) — мелкие файлы в реальных данных дублируются сильнее всех. Для строго-уникального файла проигрыш — арифметика (payload + refs + манифест), порога не требует. **NO-GO** размерного правила; маршрутизация router'а (AH-18) — по измеренной дубликатности.
