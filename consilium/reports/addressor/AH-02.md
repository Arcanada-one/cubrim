## Каноническая формулировка (если X → Y на Z, потому что M)

Если представить матрицу как глобальный CAS неизменяемых CDC-чанков, то net-байты на повторно встречающемся контенте упадут до последовательности 32B хэш-ссылок, потому что получатель уже хранит чанки, а CDC устойчив к сдвигам.

## Поля карточки

- **Физическая модель / каталог:** exact chunk dedup по каталогу; получатель хранит чанки
- **Класс данных (Z):** OS-образы, пакеты, пересылаемые файлы, бэкапы
- **Address target:** 32 B
- **Predicted lever (предсказание, НЕ измерение):** hit_rate*(1-0.4%) по массе; литература enterprise 10-30x (внешняя)
- **Ceiling-категория:** `identity-dedup`
- **Falsification test:** chunk-hit-rate по массе на кросс-девайсной смеси; <30% -> только режим router (AH-18)
- **measured_result:** null — измерений не было, статус OPEN честен
- **code_ref:** null — кода ещё нет
- **Source:** epic-brief C + CDC/Rabin literature

## total_cost = address + metadata + residual + amortized(matrix/catalog/distribution/sync/integrity)

address: 32 B на чанк при hit · metadata: манифест файла (список чанков, длины, порядок) · residual: новые чанки целиком + их upload в матрицу · amortized: хранение CAS×время + каталог (AH-09/10) + integrity (AH-21) + первая передача каждого блока (AH-19).

## Честный потолок / граница no-win

Не выигрывает: уникальные данные (hit→0) — хэши несжимаемы, манифест — чистый оверхед; проигрыш локальному сжатию гарантирован.

## Авторский разбор (из синтез-отчёта волны 1)

### AH-02 · Матрица-как-CAS чанков (content-addressable store) — `identity-dedup`
**Если** представить матрицу как глобальный CAS неизменяемых CDC-чанков (Rabin content-defined chunking, средний чанк ~8 KiB), накопленных с ранее виденных данных на многих устройствах, **то** метрика net-передаваемых байт на классе **повторно встречающегося контента (OS-образы, пакеты/библиотеки, пересылаемые файлы, бэкапы)** упадёт до последовательности хэш-ссылок (~32 B / 8 KiB ≈ 0.4% на чанк при hit), **потому что** получатель уже физически хранит чанки, а CDC устойчив к вставкам/сдвигам.
- Физическая модель: облачный/распределённый чанк-стор + локальный кэш; каталог = хэш-индекс чанков.
- Address target: 32 B SHA-256 на чанк + манифест файла (соответствует операторским 16–64 B на ссылку).
- Predicted lever: выигрыш = hit_rate × (1 − 0.4%) по массе; литература по enterprise-backup dedup даёт 10–30× (внешняя ссылка, НЕ наше измерение).
- Falsification: измерить chunk-hit-rate по массе на реалистичной кросс-девайсной смеси; если <30% массы — класс узок, GO только как режим в router (AH-18).
- Честный потолок: на уникальных данных hit→0 и схема ПРОИГРЫВАЕТ локальному сжатию (хэши несжимаемы; манифест — чистый оверхед). Первое появление чанка платит полную цену + upload (AH-19).
- total_cost: addresses + манифест + residual (новые чанки целиком) + amortized(хранение всего CAS × время + каталог AH-09/10 + доверие AH-21).

## Probe result — W1-competitive-v1 (2026-07-14, MEASURED, competitive)

Charged-адресатор ПОБЕДИЛ локальное сжатие на реальном корпусе: local zstd-3 ratio **0.5562** vs addresser charged **0.4781** (residual-чанки zstd-3 + refs 42.97 МБ + каталог 21.69 МБ) → **выигрыш 7.81 пп** от исходного размера, при честно измеренном штрафе чанк-гранулярности 11.6 пп. Оба плеча — один кодек (уровень сокращается из вердикта). Критерий оператора (net-байты < локального сжатия при ссылке ≪ payload) выполнен на single-host срезе; caveat worktree-копий записан; GO — после кросс-девайсного подтверждения (AH-23, в работе). Числа в БД (`measured_result.competitive`).

## Verdict — GO (2026-07-14, W1-crossdevice-v1 + W1-competitive-v1, MEASURED)

Chunk dup-mass **43.01%** на 3-хостовом объединении (falsification-бар <30% не сработал; кросс-хостовый срез 16.21%) + измеренный competitive-выигрыш charged-адресатора над локальным zstd-3: 0.4781 vs 0.5562 (**+7.81 пп**) при штрафе чанк-контекста 11.6 пп. **GO.** Мульти-девайс эмулирован хэш-агрегацией; payload не покидал хосты.
