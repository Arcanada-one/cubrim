# FH3-04 — Sparse Gated Linear Network (GLN) как предиктор-компонент CM: локальное обучение без backprop, hashed n-gram контексты → constant-time integer-лукап — target: text (усилить −12.1% margin) + code/database/exe backend

**Волна:** WAVE 3 (2026-07-22, Fable 5). **Статус:** PROPOSED, не запускалось.

## Механизм

GLN (Veness et al., DeepMind, AAAI 2020) — семейство нейросетей БЕЗ обратного распространения: каждый нейрон сам предсказывает целевой бит и обучается локальным online-gradient-descent по СВОЕМУ логлоссу; контекст «гейтит» (выбирает) активное подмножество весов. В компрессорном воплощении (G9-V1, AIT-2026 challenge): **разреженные GLN-нейроны с хэшированными байтовыми n-gram контекстами порядков 1,2,3,4,6,8,16 — каждый контекст выбирает ОДИН свой вес на предсказание**, что сохраняет адаптивность GLN, но сводит инференс и обучение к **constant-time табличным лукапам** (как раз топология Cubrim MODE_CM). Детерминированная инициализация весов → воспроизводимость.

Перенос: добавить GLN-слой как ещё один вход в существующий 2-layer logistic mixer Cubrim (рядом с order-0..11 counters, match-models, word-models). GLN даёт иную функцию агрегации контекстов (мультипликативный гейтинг + локальный лосс), чем линейный logistic-mixer — комплементарный сигнал. Integer fixed-point веса, детерминизм, fail-closed, за competitive-min.

## Чем берёт лидера

Text-margin Cubrim vs ppmd −12.1% — хотим БОЛЬШЕ запаса. ppmd берёт текст сильным контекст-миксом порядка. GLN-компонент добавляет **backprop-free локально обучаемый нелинейный смеситель контекстов**, доказанно сильный в компрессии (лежит в основе призового G9-V1 и генеалогии cmix-компонентов). Ключ — он ЛОКАЛЬНО-обучаемый и константно-дешёвый (в отличие от рекуррентных сетей FH2-01), т.е. реалистичен для rail без 100× замедления.

## Научный источник (2024–2026)

- **«The 2026 Algorithmic Information Theory Data Compression Challenge» (arXiv 2606.17712)** — G9-V1: sparse GLN нейроны, hashed n-gram контексты 1..16, один вес на контекст, constant-time лукап; конкурентный результат в челлендже.
- **Gated Linear Networks** (Veness et al., AAAI 2020; arXiv 1910.01526) + **Gaussian GLN** (NeurIPS 2020) — база: backprop-free, локальный лосс, online GD, детерминированная инициализация.

## Оценка выигрыша (с чарджем)

- text: **−1.5…−4% self** (грубо; GLN-компонент как ОДИН доп.вход в уже сильный микс — инкремент, не революция; лит. показывает GLN конкурентным, но Cubrim CM уже имеет order-0..11 + match + word, часть сигнала перекрыта). На code/database — аналогично −1…−3%. exe — доборно.
- Чардж: веса GLN — АДАПТИВНЫЕ (обучаются онлайн из детерминированного нуля, **wire=0**, как counters) → нет передачи таблиц (анти-Gotcha-#6 по построению). Стоимость — память под хэш-таблицы весов (десятки–сотни МБ, как у текущих CM-контекстов) + такты на лукапы. Декодер симметричен энкодеру (та же цена).

## Отличие от H-* / FH-* / FH2-*

- **FH2-01 (крошечный RWKV/GRU как вход микшера)** — РЕКУРРЕНТНАЯ сеть с backprop-through-time-обученными (офлайн, вшитыми) весами; GLN — **feedforward, локальный лосс, backprop-free, обучается ОНЛАЙН из нуля** (wire=0, не вшитые веса) и сводится к table-lookup. Иной механизм обучения и иной профиль стоимости (константный лукап vs матричные умножения RNN).
- **FH-01 (bit-history StateMap + collision-resistant hash)** — счётчики/state-machine; GLN — обучаемый гейтированный линейный смеситель поверх тех же хэш-контекстов (нелинейная агрегация, которой у StateMap нет).
- **FH-05 (2-layer logistic mixer)** — фиксированная логистическая топология; GLN добавляет мультипликативный гейтинг + per-neuron локальный лосс как НОВЫЙ вход, не замена микшера.
- Отвергнутый «двух-order mixing oracle без обучаемого mix» — GLN именно ОБУЧАЕМЫЙ (online GD), не оракул.

## ВЕРДИКТ (2026-07-23, ВЕТКА-B) — NO-GO

Probe (real numbers, wire=0, online adaptive log-loss на dickens 1M; harness `probes-b/fh3_04_gln_v4.py`). GLN как доп.вход честного логистического CM-микса, прогрессивное усиление базы:
- o0..8: GLN −0.43% (corr 0.94); +o12/16+match (base 2.31): −0.39% (corr 0.90); **+APM/SSE (base 2.23): −0.08%**.

Одна APM-ступень субсумировала ~80% вклада GLN. Причина: мультипликативный gating GLN в основном исправлял miscalibration логистического микса — функция SSE/APM, уже присутствующего в Cubrim CM2 (цепочка APM + 2 indirect StateMap + dual-counter). GLN standalone 2.87 bpc слабее базы. Слабая база щедра к входу → −0.39% = верхняя граница; реальный чемпион (~1.8 bpc) поглотит остаток → ~0. Оценка −1.5…−4% не достигнута. NO-GO (частный случай Gotcha #11). Journal-only, не БД.
