# FH2-09 — Пер-файловое обучаемое контекст-дерево (JPEG XL MA-tree класс) для image-профиля с оплаченной передачей дерева — target: image (ptt5 #5, удержание mr/x-ray)

**Волна:** WAVE 2 (2026-07-21, Fable 5). **Статус:** PROPOSED, не запускалось.

## Механизм

JPEG XL modular mode кодирует пиксели/остатки через **meta-adaptive (MA) дерево решений, ОБУЧАЕМОЕ на самом изображении и передаваемое в потоке**: внутренние узлы тестируют свойства окружения (соседние пиксели/остатки, градиенты, позиция), листья — свои адаптивные распределения. Перенос в Cubrim image-профиль:

1. Кодер на первом проходе жадно строит дерево (стандартный CART-подобный сплит по снижению энтропии) над фиксированным набором из ~10–15 целочисленных свойств (N, W, NW, градиенты, x mod период, битовая плоскость);
2. Дерево сериализуется в заголовок (**полностью чарджится**; типично сотни байт — единицы КБ);
3. Декодер читает дерево и ведёт те же листовые адаптивные счётчики → арифметика. Всё целочисленно, детерминированно, fail-closed.

Для ptt5 (bilevel) свойства — биты соседних пикселей двух строк (JBIG-шаблон как ЧАСТНЫЙ СЛУЧАЙ, который дерево найдёт само, если он оптимален); для mr/x-ray — 16-битные остатки MED16.

## Чем берёт лидера

xz видит факс как байтовые повторы (+21.3% нашего проигрыша на ptt5); фиксированные шаблоны (JBIG/CALIC) — одна модель на все изображения. MA-дерево **подгоняет структуру контекстов под конкретный файл** и честно платит за подгонку передачей дерева — выигрывает там, где у файла нестандартная геометрия/растр.

## Научный источник (2020–2026)

- **JPEG XL** (ISO/IEC 18181, 2022; Alakuijala et al., «JPEG XL next-generation image compression», SPIE 2020): modular mode / MA-trees — рабочий SOTA-механизм lossless-изображений; jxl lossless стабильно бьёт PNG/WebP-lossless на 20–35% (лит.).
- FLIF/MANIAC (предшественник, 2016) — генеалогия механизма; свежесть — зрелая стандартизованная версия JXL 2020–2022.

## Оценка выигрыша (с чарджем)

- ptt5: мы 0.0943, xz 0.0777; JBIG-класс (FH-13) целится в лит-потолок ~0.045–0.06; MA-дерево — тот же класс с автоподбором шаблона: **потолок аналогичный, робастность выше** (не привязан к угаданной ширине строки). Оценка на ptt5 −30…−50% self (грубая, лит-якорь JBIG/JXL на факсах).
- mr/x-ray: −1…−4% поверх MED16 (грубо; уже #1 — это удержание).
- Чардж: дерево (сотни байт — КБ) + 1 profile-байт; двухпроходный кодер (медленнее ×1.5–2), декодер быстрый (один лукап-путь по дереву на пиксель).

## Cheap probe (GO/NO-GO)

1. **Минуты, без кода:** `cjxl -d 0` (lossless) на ptt5/mr/x-ray → сравнить с нашими числами и xz. Если jxl не бьёт наш текущий min — класс не даёт запаса, NO-GO немедленно.
2. **День, Python:** CART-дерево над 12 свойствами ptt5 + реальные адаптивные листовые счётчики, end-to-end с чарджем сериализованного дерева (Gotcha #6: дерево — отдельная ветвь декодера, отдельный cost-term).

## Риск / стоимость

- 3–5 дней (построитель дерева + сериализация + листовые кодеры). Арх-риск средний (новый подформат), RT-риск средний — гасится fail-closed + competitive-min. Приоритет: после text/exe/binary (тип уже #1; ptt5 — единственный проигранный файл).

## Отличие от H-* / FH-*

- **FH-13 (JBIG)** — ФИКСИРОВАННЫЙ 10–12-битный шаблон; FH2-09 — **обучаемая на файле структура контекстов с оплаченной передачей** (супермножество: дерево может выучить JBIG-шаблон, но не обязано). Если FH-13 пойдёт первым — FH2-09 меряется как инкремент поверх.
- **FH-14 (CALIC)** — фиксированные контекст-бакеты остатков; та же разница.
- H-39/H-59/H-60/H-63 — выбор ПРЕДИКТОРА (MED/Paeth), не структуры контекстов.
- Передача дерева ≠ закрытая φ-ветка: дерево — это МОДЕЛЬ (сотни байт, не перестановка данных); Gotcha #6-чардж обязателен и включён в пробу.
