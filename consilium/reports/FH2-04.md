# FH2-04 — Similarity-переупорядочивание крупных сегментов (tar-члены / статьи) с оплаченной грубой перестановкой — target: exe (mozilla) + code (samba), запас на text

**Волна:** WAVE 2 (2026-07-21, Fable 5). **Статус:** PROPOSED, не запускалось.

## Механизм

1. Разрезать файл на **крупные сегменты по естественным границам**: tar-члены (mozilla = 525 членов, ustar-парс уже написан в FH-18; samba — tar исходников), либо content-defined чанки 256 КБ+ для монолитов.
2. Посчитать дешёвую сигнатуру каждого сегмента (байтовая гистограмма / minhash k-грамм).
3. **Переупорядочить сегменты по похожести** (жадный nearest-neighbor / 1-D проекция) — похожие .so-библиотеки, дублирующиеся исходники, родственные статьи становятся СОСЕДЯМИ.
4. **Передать перестановку явно и оплатить её**: N·⌈log2 N⌉ бит (mozilla: 525×10 бит ≈ 660 Б на 51 МБ — 0.0013%). Декодер раскодирует поток и восстанавливает исходный порядок.
5. Дальше — существующие rails (LZ-CM / MODE_CM / bwt) через competitive-min.

## Чем берёт лидера

7z берёт mozilla 64-МБ словарём, дотягивающимся до похожих членов через весь tar. Переупорядочивание сближает похожие члены на дистанцию, где их видит ЛЮБОЕ окно и где CM match-модель/контексты ещё тёплые. Это дешёвый способ купить «длинное окно» без длинного окна — и он аддитивен и к LZ-rail, и к MODE_CM.

## Научный источник (2020–2026)

- **fx2-cmix — победитель Hutter Prize (сентябрь 2024, Orav & Knoll, 110 793 128 Б на enwik9)**: компонент «Article Ordering» — статьи эмбеддятся, t-SNE проецирует в 1-D, корпус переупорядочивается; выигрыш реальный на призовом бенчмарке. Мы переносим механизм с wiki-статей на container-члены.
- 7z/rar эвристика сортировки файлов по расширению/имени в solid-архивах — многолетний практический аналог на уровне архива; здесь то же самое ВНУТРИ файла-контейнера.

## Оценка выигрыша (с чарджем)

- **Неизвестен до пробы — и проба почти бесплатна.** Верхняя граница ограничена межчленной избыточностью на дистанции > текущего окна/блока; для mozilla (сотни родственных бинарей одной сборки) грубая вилка **−2…−8%**; для samba (повторяющиеся заголовки/копирайты исходников) −1…−4%. Для enwik8 применимо только при content-defined разрезе — вилка уже, −0.5…−2% (грубо).
- Чардж: перестановка (сотни байт) + границы сегментов (у tar выводятся из самих данных — 0; у content-defined — 4 Б/чанк) + возможная потеря непрерывности CM-состояния на швах. Всё входит в end-to-end пробу.

## Cheap probe (GO/NO-GO)

**Часы, Python + существующий CLI, без нового Rust:** распарсить mozilla на 525 членов (парсер из FH-18), пересобрать tar в similarity-порядке (жадный по гистограммной близости), прогнать ОБА варианта через текущий cubrim CLI и через xz; сравнить с чарджем 660 Б + заголовок. GO если reorder даёт ≥1.5% на любом rail. Повторить для samba. NO-GO критерий жёсткий и мгновенный.

## Риск / стоимость

- Интеграция при GO: 2–3 дня (tar-детект уже есть; обратная сборка byte-exact с паддингами — FH-18 это уже делал с cmp=0). RT-риск средний, гасится fail-closed + competitive-min.
- Риск: межчленные повторы могут уже покрываться нынешним окном (mozilla кодируется блоками — тогда выигрыш уйдёт в 0; проба покажет).

## Отличие от H-* / FH-* и закрытых веток — КРИТИЧЕСКИЙ ПУНКТ

- **Закрытая ветка «φ с передаваемой перестановкой» (Gotcha #7 / CUBR-0032) — НЕ дубль:** там перестановка **по-значная** (стоимость ~n·log n бит на n ЗНАЧЕНИЙ ≈ размер файла, информационное сохранение делает выигрыш невозможным). Здесь перестановка **по-сегментная**: N≈500 объектов, стоимость сотни байт — на 5 порядков меньше данных; информационное равенство Gotcha #7 не запрещает выигрыш, когда карта грубая, а локальность переносится крупными кусками (BWT-исключение того же рода). fx2-cmix — экспериментальное доказательство, что класс работает.
- FH-18 — Alpha-BCJ per member (переписывание байтов, NO-GO); здесь члены НЕ модифицируются, меняется только порядок. Переиспользует парсер FH-18.
- FH-15 (persistent match) решает ту же дальнодистантность моделью; эти механизмы аддитивны, проба ранжирует их дешевизну.
- Cross-file dedup (закрыт) — межфайловый словарь; здесь intra-file, ничего внешнего.
