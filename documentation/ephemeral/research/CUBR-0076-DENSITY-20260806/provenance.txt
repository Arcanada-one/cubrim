Method:
- slices: each sample cut at 65,536-byte boundaries (the chunked path's own
  block size; slice k = bytes [k*65536, (k+1)*65536) — offsets and slice
  sha256 in slices.tsv), so every unit is a single cube and the per-scheme
  profiler totals are exact per-slice wire sizes.
- per slice: `cubrim compress --value-scheme bwt-rans <slice>` with
  CUBRIM_PROFILE=1. Requesting a rans-family member runs the full committed
  8-way scheme competition (codec.rs encode_rans_family_value_stream) and the
  profiler records each candidate's complete wire stream (tables included by
  wire layout — Gotcha #6 satisfied by construction). --value-scheme is an
  existing CLI measurement knob; encoder DEFAULTS are untouched and the
  emitted archive is still the stock competitive winner (CM2 on all text).
- static class = {vs_bwt_rans, vs_bwt_huff, vs_t4_huff, vs_order2_rans,
  vs_lz_rans} (schemes 7,6,4,8,12 — all tables on the wire, no decode-time
  adaptation). adaptive class = {vs_adaptive, vs_ctxmix, vs_geomix}
  (schemes 9,10,11 — decoder rebuilds the model online).
- static-forced blob per slice = base_blob - winner_stream + min(static
  streams), clamped at raw-store cost (len+13); winner = argmin over the 8
  streams with the rail's earlier-listed tie order. woff2 resolves to RAW
  parity (delta 0), matching the census.
- whole-file profiled encodes of the 4 multi-block samples additionally
  capture the MODE_LZ candidate (lz_prepass) — the codec's whole-file
  LZ+entropy shape. Caveat recorded: MODE_LZ sub-streams may select adaptive
  sub-coders per file, so it is an optimistic (lower-bound-flavoured) proxy
  for a static scheme.
