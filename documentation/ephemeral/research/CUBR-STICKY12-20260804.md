## Question and boundary

The earlier `CUBR-PROFFOUND-20260804` run found `FINAL:geomix` on all 384
value-scheme blocks of `x-ray.2m` and `ooffice.2m`. This run measures the
remaining ten Silesia files with the same 2 MiB-prefix protocol.

`FINAL:*` is the per-block final value-scheme winner. It is different from the
ordinary candidate `wins` counters, which count running-minimum improvements.
`NONE` below means the input round-tripped but did not enter the inner
value-scheme rail, so there were zero final-winner blocks to classify; it is not
a failed observation.

This is attribution evidence only. It does not measure a sticky implementation,
its ratio cost, or its speed benefit, and it does not reopen NEW-29's KILLED
verdict.

The two earlier rows remain unchanged:

| file | final distribution | RT |

| `ooffice.2m` | `geomix=384` | PASS |

Across all twelve measured 2 MiB slices:

- Six files reached the value-scheme rail: `x-ray.2m`, `ooffice.2m`,
  `mozilla`, `mr`, `nci`, and `sao`.
- Six files did not reach it: `dickens`, `osdb`, `reymont`, `samba`,
  `webster`, and `xml`; each still has a byte-exact RT PASS.
- Of the six rail-reaching files, three are split: `mozilla` has 325/384
  `geomix` and 59/384 `lz_rans`; `nci` has 237/384 `geomix` and 147/384
  `lz_rans`; `sao` has 383/384 `geomix` and 1/384 `ctxmix`.
- Summed over the rail-reaching files, the final rows contain 2,097 `geomix`,
  206 `lz_rans`, and 1 `ctxmix` blocks out of 2,304 final-winner blocks.

## Verdict and limits

The universal fixed-winner hypothesis is false on this corpus. `geomix` is
dominant in the rail-reaching files, but three files contain a different final
winner, and two of those have a material `lz_rans` share. A one-pin-per-file
lever is therefore insufficient as written; any future design needs to learn
or recheck the winner at block level. This is a distribution finding, not a
claim that an adaptive implementation would be worthwhile.

The run does not measure sticky speedup, ratio delta, or benefit. It does not
generalize beyond these 12 measured 2 MiB slices, does not claim an N=24
aggregate, and does not reopen NEW-29's pre-registered KILLED verdict. No DB
write was made.
